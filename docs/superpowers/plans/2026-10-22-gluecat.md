# gluecat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** gluecat, an AWS Glue Data Catalog client for Apache Spark: a catalog plugin that puts each named Spark catalog on its own AWS Glue Data Catalog (own catalog ID, own IAM role), loads and creates Delta tables there, and reads other data-source tables, without the Hive metastore client.

**Architecture:** `GlueCatalog` (the class users configure) routes Spark's `TableCatalog` / `StagingTableCatalog` / `SupportsNamespaces` calls to a format-agnostic `GlueCoreCatalog`, which talks to Glue through a small `GlueApi` trait (SDK v2 adapter in production, in-memory in unit tests) and converts entries with a pure `EntryConverter`. Delta support wraps Delta's own `DeltaCatalog` around the core for loading, and runs creates and replaces as path-based Delta operations followed by a Glue write, because Delta only registers tables through a wrapped catalog when that catalog is Unity Catalog.

**Tech Stack:** Scala 2.12.21 / 2.13.18, Maven 3.9 (wrapper), scala-maven-plugin 4.9.2, AWS SDK v2 2.24.6 (`glue`, `sts`) as a `provided` dependency, ScalaTest 3.2.20 run through JUnit 4 (surefire for unit tests, failsafe for integration tests against the module's jar), MiniStack `ministackorg/ministack:1.5.31` as Glue/STS/IAM in CI, GitHub Actions, Maven Central via central-publishing-maven-plugin 0.12.0.

**Spec:** `docs/superpowers/specs/2026-10-22-gluecat-design.md`

Compile and test against this one SDK version; newer SDK versions on the user's classpath are supported, older ones are not. Scala 2.12.21, 2.13.18. ScalaTest 3.2.20, scalatestplus `junit-4-13` 3.2.20.0, junit 4.13.2.
- Package `io.github.sdaberdaku.gluecat`. Entry class `io.github.sdaberdaku.gluecat.GlueCatalog`.
- `GlueCatalog` never implements `CatalogExtension`, `ViewCatalog` or `FunctionCatalog`.
- Never reference Spark's `private[sql]` objects: `CatalogV2Util`, `V1Table` (use the reflection bridge), `IdentityTransform` / `FieldReference` (use `Transform.name()` / `references()` and `Expressions.identity`).
- Never pass a catalog identifier to `DeltaCatalog.createTable` / `stageCreate` / `stageReplace` / `stageCreateOrReplace`; Delta creates and replaces run with the path identifier ``Identifier.of(Array("delta"), <location>)``.
- Never name a class `io.unitycatalog.*`.
- Shared code compiles for Scala 2.12 and 2.13: use `scala.collection.JavaConverters._` (not `CollectionConverters`), no 2.13-only collection methods.
- Shared code must not use Java 9+ APIs (`-release:8` enforces this on JDK 9+ builds of the 3.5 modules).
- The AWS SDK v2 (`glue`, `sts`) is `provided`: the jars contain no SDK classes and expect the SDK on the Spark classpath (on Spark 4.x the `bundle` that `hadoop-aws` brings; on Spark 3.5 the user adds the v2 modules). The SDK's default HTTP client resolution applies; the library never sets an HTTP client.
- Test fixtures and docs use generic names only (`acct_a`, `111111111111`, `s3://bucket-a/...`). No company, customer, account or bucket names.
- Commit messages: plain, no attribution lines of any kind.
- Database and table names are lowercased before every Glue call and in every identifier returned to Spark.
- Every `UpdateTable` passes the `VersionId` read before the change; `SkipArchive` follows `glue.skip-archive` (default true).
- DROP never deletes data; `purgeTable` throws.
- Every Glue parameter the catalog owns (`EXTERNAL`, `table_type`, `transient_lastDdlTime`, `spark.sql.*`) is hidden from Spark's table properties; every other parameter is preserved on updates.

## Decisions that refine the spec (made while planning, from source checks)

- `V1Table` and `CatalogV2Util` are `private[sql]` in Spark 3.5.9 and 4.2.0. Unity Catalog's connector constructs `V1Table` by reflection; this plan does the same (`V1TableBridge`) and re-implements the few `CatalogV2Util` helpers it needs (`TableProperties`, identity-transform handling).
- Spark 4.x makes the `StructType` overloads of `createTable` / `stageCreate` / `stageReplace` / `stageCreateOrReplace` default methods that throw unless overridden, and the `Column[]` and `TableInfo` overloads delegate down to them; in 3.5 the `StructType` overloads are abstract. Implementing the `StructType` overloads therefore covers every Spark version.
- Dependency injection into `GlueCatalog` (which Spark instantiates with a no-arg constructor) is through two `protected` factory methods, `newGlueApi` and `newFormatSupport`, which a test subclass overrides. There is no client-factory interface: it would have one production implementation, and overriding `newGlueApi` already lets a test substitute the Glue layer.
- Glue requests are recorded for the isolation tests by a `GlueRequestObserver` (library type) inside `SdkGlueApi`. Every Glue call the adapter makes reports its operation name and `CatalogId`.
- `client.credentials-provider` loads the user's class with `Class.forName`, instantiates it through a static `create(java.util.Map)`, else a static `create()`, else the no-arg constructor, and casts the instance to `software.amazon.awssdk.auth.credentials.AwsCredentialsProvider`.
- Entry format for the `StorageDescriptor` (from `HiveExternalCatalog.createDataSourceTable`, Spark 4.2.0): Delta tables get real columns, no partition keys, real location and `table_type=DELTA`. Providers with a Hive SerDe mapping (parquet, orc, avro, textfile, sequencefile, rcfile) and only Hive-compatible types get the Hive-compatible form: real SerDe/input/output formats, data columns, partition columns as `PartitionKeys`, real location. Every other provider gets Spark's specific form: `LazySimpleSerDe` / `SequenceFileInputFormat` / `HiveSequenceFileOutputFormat`, one column `col array<string>` (comment `from deserializer`), partition columns as `PartitionKeys`, location `<location>-__PLACEHOLDER__`.
- Delta's `UpdateCatalog` hook checks `spark.sessionState.catalog.tableExists`, which qualifies the identifier to the session catalog and ignores its catalog field (Spark 4.2.0 `SessionCatalog.tableExists` / `qualifyIdentifier`), so with the hook on and a same-named table in `spark_catalog` it would write there. Decision: `GlueCatalog.initialize` fails with a clear error when `spark.databricks.delta.catalog.update.enabled` is `true`, and, since it is a runtime conf, `DeltaFormatSupport` repeats the check before every Delta operation by name (Task 13 showed the hook, turned on at runtime, rewriting a same-named table in the session's v1 catalog in Session mode).
- Delta's `ALTER TABLE ... SET LOCATION` (`AlterTableSetLocationDeltaCommand`) writes through the session catalog. `GlueCatalog` handles `SetProperty("location")` itself through the core and never passes it to Delta.
- MiniStack 1.5.31 returns every table or database in one page (no `NextToken`), does not lowercase names, deletes a database's tables with the database, requires no IAM role for `AssumeRole` or `AssumeRoleWithWebIdentity` and accepts any web identity token (AUTH off), and maps both sessions to the role's account. SDK 2.24.6 ignores `AWS_ENDPOINT_URL`, so STS calls (the assume-role client and the SDK's web identity provider) reach MiniStack only through the test-classpath interceptor `it.StsToMiniStack`. Pagination and lowercasing are unit-tested against a stub `GlueClient`; `dropNamespace` without `CASCADE` lists tables first.
- Glue's `DeleteDatabase` deletes the database's tables; `dropNamespace(ns, cascade = false)` must check emptiness first.
- No per-Spark-version shim is needed from the source checks; the build keeps an optional `src/main/spark-${spark.minor}/scala` root for one if the matrix ever demands it.

## Review Focus

1. A table whose schema JSON is longer than `spark.sql.sources.schemaStringLengthThreshold` (default 4000) must round-trip through `numParts` / `part.N` and load again; boundary at exactly 4000 and 4001 characters. Test in Task 7.
2. Mixed-case identifiers (`acct_a.MyDb.MyTable`) must resolve to the same Glue table as the lowercase form in every operation, including `tableExists`, and listings must return lowercase names. Tests in Task 9 and Task 10.
3. A database `LocationUri` with a trailing slash must not produce `//` in derived managed-table locations; a `warehouse` with a trailing slash likewise. Test in Task 9.
4. `saveAsTable` with `option("path", ...)` passes both `location` and `option.path`; `CREATE TABLE ... LOCATION` passes only `location`. Both must create the Delta table at that path and the Glue entry with that location. Test in Task 11.
5. A Glue database that contains views and Iceberg tables: `listTables` skips views and lists Iceberg tables; loading the Iceberg table fails with the Iceberg pointer; loading the view fails with the view error. Test in Task 10.

- [ ] **Step 3: Implement `DeltaFormatSupport`**

- `loadTable(ident)` and the time-travel overloads → `delta.asInstanceOf[TableCatalog].loadTable(...)` (Delta asks `core`, turns a Delta `V1Table` into `DeltaTableV2`, passes other tables through).
- `createTable(ident, schema, partitions, props)`: `spec = TableProperties.split(props, defaultProvider)`; if `!isDelta(spec.provider)` → `core.createTable(...)`. Else, before Delta writes anything: owned keys in `spec.properties` are rejected (`core.rejectOwnedKey`), a missing database fails (`core.loadNamespaceMetadata`), and if `core.tableExists(ident)` → `TableAlreadyExistsException`; `location = core.resolveLocation(ident, spec)`; `deltaProps = props - "location" - "external" - "is_managed_location" - "option.path"`; `pathTable = delta.createTable(pathIdentifier(location), schema, partitions, deltaProps)`; `registerFromPathTable(ident, location, pathTable, spec)`; return `loadTable(ident)`.
- `registerFromPathTable`: build a `CatalogTable` from `pathTable.schema()`, `TableProperties.partitionColumns(pathTable.partitioning())`, `spec.properties`, `spec.comment`, `spec.owner`, provider `delta`, location; call `core.registerTable(ident, table)` (or `core.replaceTable` for replaces); wrap any `Throwable` from the Glue write in `DeltaCommittedButGlueFailedException(<catalog>.<db>.<table>, location, cause)` (the catalog-qualified name, so the recovery statement in its message runs as is); for a replace, a plain error saying the Glue entry keeps its previous columns and properties.
- `stageCreate` / `stageReplace` / `stageCreateOrReplace`: non-Delta → `UnsupportedOperationException`. Delta: `location` = for replace: the existing entry's location (`core.loadEntry` → `EntryConverter.location`; a non-Delta entry or a different `LOCATION` is refused, as Delta does), for create: `resolveLocation`, for create-or-replace: existing location if present else `resolveLocation`; `staged = delta.asInstanceOf[StagingTableCatalog].stageX(pathIdentifier(location), schema, partitions, deltaProps)`; return `new StagedGlueTable(staged, ident, location, mode)` that implements `StagedTable with SupportsWrite`, forwards `name`, `schema`, `partitioning`, `properties`, `capabilities`, `newWriteBuilder` to `staged`, and in `commitStagedChanges()` calls `staged.commitStagedChanges()` then loads the path table (`delta.loadTable(pathIdentifier(location))`) and registers (create) or replaces (replace / create-or-replace when the entry exists) in Glue; `abortStagedChanges()` → `staged.abortStagedChanges()` only.
- `alterTable(ident, changes)`: `entry = core.loadEntry(ident)` (missing → `NoSuchTableException`); if not Delta → `core.alterTable`. Else: `locationChanges = changes.filter(c => c is SetProperty && property == "location")`; `core.alterTable(ident, locationChanges)` when non-empty; `delta.alterTable(ident, rest: _*)` when `rest` non-empty and, if `rest` contains a column change (`AddColumn`, `DeleteColumn`, `RenameColumn`, `UpdateColumnType`, `UpdateColumnComment`, `UpdateColumnNullability`, `UpdateColumnPosition`), `syncSchema(ident)` (property-only changes stay in the Delta log); return `loadTable(ident)`.
- `invalidateTable(ident)`: `syncSchema(ident)`.
- Path identifiers (R38): `GlueCoreCatalog.loadEntry` answers `None` and `dropTable` `false`, without a Glue call, for an identifier with one namespace part whose name is an absolute Hadoop `Path` (any format). `DeltaFormatSupport` forwards `createTable`, `stage*`, `alterTable`, `invalidateTable` on ``delta.`<path>` `` to `DeltaCatalog` unchanged, with no Glue write. Every Delta create or stage first requires `spark.sql.runSQLOnFiles=true` (`IllegalStateException` otherwise). REPLACE compares locations as normalised URIs (`new Path(x).toUri`: scheme, authority and path, no trailing slash).
- `private syncSchema(ident)`: `core.loadEntry(ident)`; if absent or not Delta → no-op. Else `table = delta.loadTable(ident)` (the `DeltaTableV2`), build the `CatalogTable` from the existing entry (`EntryConverter.toCatalogTable`) with `schema = table.schema()` and `partitionColumnNames = TableProperties.partitionColumns(table.partitioning())`, then, only when the schema or partition columns differ, `core.replaceTable(ident, updated)` (`VersionId`-guarded, unknown parameters preserved); wrap `GlueApiException` with `CatalogErrors.translate`. A REFRESH on a Delta table therefore needs Glue write access.
- `GlueCatalog.newFormatSupport`: `if (DeltaFormatSupport.available) new DeltaFormatSupport(...) else new PassThroughFormatSupport(core)`; `available` loads `org.apache.spark.sql.delta.catalog.DeltaCatalog` through the thread context class loader (the one Spark loads catalog plugins with) and returns false on `ClassNotFoundException`.
