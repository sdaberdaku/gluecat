# gluecat 1.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** gluecat 1.1.0: per-catalog Hadoop options (`hadoop.*`) with the catalog's IAM role inherited by S3A, Iceberg-style `http-client.*` settings for the Glue and STS clients, an integration suite that runs under IAM enforcement with the minimal Glue policy, and a documentation page on catalogs across AWS accounts.

**Architecture:** `GlueCatalogOptions` gains the `hadoop.*` and `http-client.*` groups; a pure `S3RoleDefaults.derive` turns the catalog's assume-role settings into S3A keys; `GlueCatalog.initialize` computes the effective per-table Hadoop options once and hands them to the core and to the Delta support, which add them to the storage properties of every `CatalogTable` they return and as `option.<key>` entries on Delta's by-path creates and replaces (Delta and Spark both copy such keys into the Hadoop configuration of the table's files). `GlueClients` builds an SDK HTTP client from `http-client.*`. Nothing injected is ever written to Glue. CI's MiniStack runs with `AUTH=true` and every suite's main catalog assumes a role carrying exactly the ten Glue actions gluecat uses.

**Tech Stack:** as 1.0.0 (Scala 2.12/2.13, Maven wrapper, AWS SDK v2 2.24.6 `provided`, ScalaTest via JUnit, surefire `*Suite` / failsafe `*IT`, MiniStack 1.5.31), plus `hadoop-aws` in test scope for the S3A integration tests and `software.amazon.awssdk:apache-client` / `url-connection-client` 2.24.6 as `provided` + `optional`.

**Spec:** `docs/superpowers/specs/2026-10-23-gluecat-1.1.0-design.md` (extends `docs/superpowers/specs/2026-10-22-gluecat-design.md`, whose binding sections still hold).

## Global Constraints

- All 1.0.0 Global Constraints hold (`docs/superpowers/plans/2026-10-22-gluecat.md`): no `private[sql]` Spark objects, Scala 2.12 and 2.13, Java 8 bytecode for Spark 3.5, no class named `io.unitycatalog.*`, Delta creates and replaces by path identifier only, lowercase names, `VersionId` on every `UpdateTable`, generic names only (`acct_a`, `111111111111`, `s3://bucket-a/...`), plain commit messages.
- Work on branch `feature/1.1.0`; `main` is protected (pull requests only, required check `ci-ok`, branch up to date, administrators included). The branch is merged through a pull request once `ci-ok` is green. Pull requests run the full matrix.
- New option keys, exactly: `hadoop.<key>` (any key), `http-client.type`, `http-client.proxy-endpoint`, `http-client.proxy-use-system-property-values`, `http-client.proxy-use-environment-variable-values`, `http-client.urlconnection.socket-timeout-ms`, `http-client.urlconnection.connection-timeout-ms`, `http-client.apache.socket-timeout-ms`, `http-client.apache.connection-timeout-ms`, `http-client.apache.connection-acquisition-timeout-ms`, `http-client.apache.connection-max-idle-time-ms`, `http-client.apache.connection-time-to-live-ms`, `http-client.apache.expect-continue-enabled`, `http-client.apache.max-connections`, `http-client.apache.tcp-keep-alive-enabled`, `http-client.apache.use-idle-connection-reaper-enabled`. No other new key.
- Derived S3A keys (spec "Decided"), exactly: `fs.s3a.aws.credentials.provider` = `org.apache.hadoop.fs.s3a.auth.AssumedRoleCredentialProvider`; `fs.s3a.assumed.role.arn` = `client.assume-role.arn`; `fs.s3a.assumed.role.session.name` = `client.assume-role.session-name`; `fs.s3a.assumed.role.session.duration` = `<timeout-sec>s`; `fs.s3a.assumed.role.external.id` = `client.assume-role.external-id` when set; `fs.s3a.endpoint.region` = `client.region` when set; `fs.s3a.assumed.role.credentials.provider` = the session's `fs.s3a.aws.credentials.provider` when the session leaves `fs.s3a.assumed.role.credentials.provider` unset and that provider is not `org.apache.hadoop.fs.s3a.auth.AssumedRoleCredentialProvider`. Never `fs.s3a.assumed.role.sts.endpoint` or `.sts.endpoint.region`. Derivation only when `client.assume-role.arn` is set and `client.credentials-provider` is not.
- Precedence: explicit `hadoop.<key>` over derived over session base keys; session per-bucket keys (`fs.s3a.bucket.<name>.*`) win over everything (S3A applies them last); documented, not fought.
- Injected keys never reach Glue: `EntryConverter.toGlueTable` output for a table created or altered through a catalog with `hadoop.*` options is identical to the output without them.
- Glue actions gluecat uses, exactly: `glue:CreateDatabase`, `glue:GetDatabase`, `glue:GetDatabases`, `glue:UpdateDatabase`, `glue:DeleteDatabase`, `glue:CreateTable`, `glue:GetTable`, `glue:GetTables`, `glue:UpdateTable`, `glue:DeleteTable`. The test role's policy and the documented policy list these ten and nothing else, on `Resource: "*"`.
- MiniStack 1.5.31 facts (verified 2026-10-23): `AUTH=true` enforces IAM for users and roles; any 12-digit access key is root of that account and root keys bypass policies and skip the secret check; `AssumeRole` needs both the trust policy and the caller's `sts:AssumeRole` grant (root has everything); `POST /_ministack/reset` works under `AUTH=true`; S3 buckets are per account; Glue ignores `CatalogId` and serves the caller's account.
- `hadoop-aws` for the S3A tests, test scope only: `3.3.4` on the Spark 3.5 modules (its `aws-java-sdk-bundle` 1.12.x dependency stays, SDK v1 does not collide with v2); `3.4.1` on every Spark 4.x module, which is the hadoop-aws release built against SDK 2.24.6, with its `software.amazon.awssdk:bundle` dependency excluded and `software.amazon.awssdk:s3`, `s3-transfer-manager`, `apache-client` and `netty-nio-client` (BOM version 2.24.6) added in test scope. Spark 4.1.3 and 4.2.0 bundle Hadoop 3.4.2 and 3.5.0; S3A 3.4.1 runs on them for these tests (verified by the tests themselves, not assumed).
- The compatibility compose file (`docker/docker-compose.yml`) is not changed: its MiniStack stays with IAM off.
- Version: every `pom.xml` moves to `1.1.0-SNAPSHOT`; the release is tagged `v1.1.0` by the owner.

## Review Focus

1. A catalog with `client.assume-role.arn` on a session whose `fs.s3a.aws.credentials.provider` is already `AssumedRoleCredentialProvider` (per-bucket deployments): the base-provider row must not be derived, or S3A throws "AssumedRoleCredentialProvider cannot be its own base". Test in Task 1.
2. `hadoop.fs.s3a.aws.credentials.provider` set explicitly on a catalog with a role: the whole derived role set must still be present except the overridden key, and the override must be what reaches the table. Test in Task 1 and Task 5.
3. `CREATE TABLE ... OPTIONS (fs.s3a.endpoint='...')` by a user on a catalog that also injects `fs.s3a.endpoint`: the user's `option.` value wins on the create (it is the table's own option) and is the one persisted in Glue; the injected one is not. Test in Task 3.
4. `http-client.apache.max-connections=500` with no `http-client.type`, the exact shape of the shared chart configuration: `apache` must be implied and the Glue client built with that pool size, not silently ignored. Test in Task 2.
5. A table whose Glue location is in a bucket already opened through the session configuration earlier in the JVM: the catalog's options do not apply (Hadoop cache). The documentation must say so where the options are introduced, and the integration test must use fresh buckets per assertion so it does not depend on order. Task 5 and Task 6.
